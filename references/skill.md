## 1. 国内测绘 DXF 的常见图层（南方 CASS / GB/T 20257 地形图图式）

| 图层 | 语义 | 几何与读法 | 规划用途 |

居民地（建筑） | 闭合 LWPOLYLINE **+ 零散 LINE**（必须 polygonize，否则漏楼） | 现状台账、保留改造 footprint |
道路设施 | 边线/中线多段线 | 道路、交通底图 |
水系设施 | **非闭合 = 岸线；闭合 = 塘/池** | 溪流通道、退让线 |
等高线 | LWPOLYLINE 的 `elevation`，或 3D POLYLINE 顶点 z | 地形、梯田、竖向 |
高程点 | INSERT：属性 `height` → 插入点 z → 旁注 TEXT（三种都见过） | 地形插值、现状地坪 |
地貌土质 | 坎、陡坎、斜坡、陡崖 | 台地识别、挡墙 |
植被土质 | 植被符号 INSERT（块名为 CASS 符号码，需对照图式） | 现状林木/竹/茶分布 |
管线设施 | 电杆、管线 | 迁改与避让 |
独立地物 | 
控制点 | 点 + 编号 | **配准同名点首选** |
界址点 / 勘测定界 | 点、线 | **比地类图斑更权威的用地边界** |
宗地号 / 面积注记 | 文字 | 核对面积 |
图廓/图框 | 格网坐标标注、比例尺、**"2000国家大地坐标系,中央子午线117"** | 自动读坐标系 |
注记 | 地名、材质（水泥/碎石）、结构（砖2） | 结构层数、地面材质 |
地类图斑（国土调查） | 闭合面 | **常被当红线，但≠出让净用地** | 等 | GIS 导出 | 视内容而定 | 核对是否为法定地块 |

同一单位不同项目命名也会变；**`decode` 的"语义猜测"只是起点，逐层看几何再确认。**

## 2. 注记解析（现状台账自动化）

- 结构字：砖/混/砼/钢/木/简/破（破=破损房屋）；层数：数字（"砖2"或"砖"+"2"分开写都有）。
- 引擎取建筑轮廓内（外扩 0.5m）的 `JMD`、`ZJ` 注记解析；缺省 1 层。
- 读出来的层数仍要与甲方核对一遍；甲方口述优先，写进 `decisions[].floors`。

## 3. 红线从哪来（优先级）

1. 规划条件附图 / 出让合同宗地图（界址点坐标表）——**法定口径**
2. 勘测定界图
3. 甲方提供的红线 DWG
4. 地类图斑（`DLTB`）——只能作参考

**核对方法**：比较法定净用地与图斑的差集，说明道路用地、边角地等差异；不得拿图斑面积替代已批准的净用地。净用地口径须在工序0确认。

## 4. 坐标系

- 国内 1:500 地形图多为 **CGCS2000 3°带高斯投影**，假东 500000，单位米，`$INSUNITS` 常为 0。
- **X 带带号前缀**：X 形如 40512345.6 → 带号 40，引擎自动剥离（`zone_prefix_of`）。
- **中央子午线**：从图框注记自动读（"中央子午线11830"=118°30′=118.5；"中央子午线117"=117）。**任意带**（如 118.5）很常见，两份图不同带是常态。
- 同椭球不同带：`make_transform(cm_from, cm_to)`（pyproj tmerc）精确变换，**不要用"对齐地物"估**。
- 西安80（IAU76）/北京54（krass）：`tmerc(cm, ellps=...)`；与 CGCS2000 之间有系统差，需同名点。
- 城建/地方独立坐标系：无公开参数 → `fit_helmert(src_pts, dst_pts)` 四参数最小二乘（≥4 对同名点，看 RMS）。

## 5. 配准校验（必做）

`validate_registration([("名称",(x1,y1),(x2,y2)), ...], tol=10)`

这里的10米仅作错带粗查，不是尺寸保真验收门槛；正式生成按08的项目容差执行。

- 同名地物：塘/池心、桥、保留建筑角点、控制点、道路交叉口。
- 除同名点残差外，至少复核两个方向的已知尺寸；控制点来源和误差须记录。
- **反例**：早期正则把"中央子午线117"后一条"1985国家高程基准"的"19"吃成 117°19′，变换后偏 **几十公里**。自动读取必须校验。

## 6. 多源合并规则

- 现状建筑以**最新测绘**为准（核对日期、版本与测绘范围）；新测绘没覆盖到的保留楼用 `existing.extra` 从旧图补。
- 红线以法定口径那份为准；地形取点更密的那份（或合并）。
- 所有源统一变换进 `project.cm`。

# 02 · site_model.json 规范

`site_model.json` 是项目的**唯一真相源**：几何、属性、景观、分区、控制指标都在这里；所有图、表、DXF 由引擎从它生成。
**存放位置**：项目文件夹 `规划图源文件/site_model.json`（永久），`sources.*.file` 用相对该文件的路径。
完整实例：`examples/demo_site_model.json`。

## 约定

- 坐标：`project.cm` 指定的投影坐标，米。
- **`rot`（角度）= 拖拽板约定：屏幕顺时针为正**。引擎 `rect(cx,cy,rot,w,h)` 内部取 `-rot` 旋转到世界坐标。拖拽板导出的 JSON 可直接回写。
- `w` 为体块局部 X 向（旋转前水平边），`h` 为局部 Y 向。

> 下文为字段结构示意，数字、图层、退让和控制指标均需替换并核实；可直接运行的最小模型在examples中，不把示意参数当作项目条件。

## 顶层字段

## buildings[   ]
（**只给保留改造用**）| `null`（未落位预留）。
- 未落位预留：`"reserve": true, "area_override": 260, "geom": null` → 计入总建面，不计入已落位基底（面板应分别展示已落位与含预留口径）。
- `gfa_override`：特殊情况直接给建面（如退台、夹层）。
- `kind` 含"改造"→ 不做退让校核、出红线按 grandfather 提示；含"架空"→ 可压水体投影，退让单列说明；含"新建"却用 existing 轮廓 → 报错。

## 2. 方案 DXF 图层标准（`export_dxf` 自动生成）

| 图层 | 内容 |
|---|---|
| `00-用地红线` | 红线（ACI 1） |
| `01…0n-建筑-<业态>` | 设计建筑轮廓，按业态分层，层颜色=业态色（真彩） |
| `0n+1-现状-保留改造` / `0n+2-现状-拆除` | 现状轮廓 + "留 E07"/"拆 E08" 标注 |
| `0n+3-建筑编号` / `0n+4-建筑标注` | 编号；名称/建设方式/层数/建面/客房 |
| `0n+5-竖向-现状地坪标高` | 各建筑现状地坪（插值），**±0.00 由设计院定** |
| `20-水体` / `21-岸线` | 通道、塘、岸线 |
| `22-退让线-6m` / `23-围栏线-2m` | 按 `water.setback/fence` |
| `30-道路` / `31-桥` / `32-<景观墙等>` | |
| `40-等高线` / `41-高程点` | **等高线写真实 elevation**，高程点为 3D 点 |
| `50-说明` | 坐标系、指标（全部来自模型） |

- 格式 R2010（AC1024）。**DWG 是 Autodesk 私有格式，开源库写不可靠 → 交 DXF，设计院打开另存 DWG**，行业常规。
- 所有线要素裁到红线外扩 30m（否则溪流、退让线会拖出几百米）。
- 文字样式 `HZ`（simsun.ttf），对方缺字体会自动替换。
- 导出写明米制单位，自动回读实际DXF并对比模型核心轮廓及全部输出几何；生成 `方案.dxf.geometry-check.json`，失败不替换已有成果。关键尺寸与控制点仍须人工复核。详细覆盖与限制见 [08](08_底图冻结与几何保真.md)。

## 3. 逐栋明细 XLSX（`export_xlsx`）

- `逐栋明细`：编号/名称/业态/建设方式/占地/层数/**建面=占地×层数（公式）**/客房/现状地坪/设计要点；未落位预留斜体。
- `指标汇总`：用地、亩、基底、总建面、FAR、密度、客房、客房均建面——**全部公式引用明细**。客房均建面口径 = 客房业态建面 ÷ 客房数（与引擎一致）。
- `现状台账`、`留改拆统计`（拆除比例、拆建比，附政策口径）。
- `数据说明`：坐标系、数据来源、口径。
- 生成后用 LibreOffice 重算校验（xlsx skill 的 `recalc.py`）：**0 公式错误才交**。注意：在挂载盘上重算可能卡死 → 先拷到本地临时目录再算；清理残留进程用精确进程名，**别用 `pkill -f soffice`**（会把执行命令的 shell 自己杀掉）。

## 4. 交付说明书模板（Markdown）

1. 交付概要（深度、核心交付物、落位非示意）
2. 坐标系与配准（主坐标、变换、同名地物偏差、现状/红线各以哪份为准、**净用地口径待确认事项**）
3. DXF 图层索引

7. 现状保留/拆除（逐栋表）
8. 待设计院深化事项（见下）
9. 交付文件清单
10. 对接约定（调整落位时优先保住的硬约束；对外措辞口径）

## 5. 待设计院深化（我方不画，避免误导）

消防车道与回车场、管线综合、竖向设计与 ±0.00、结构与基础（架空体系）、日照/间距/退让合规校核、人防/无障碍/节能等专项。
**原则：只加有把握画准的图层**；需要反复对齐的（如消防车道）留给设计院，免得返工。

## 2. 现状台账（工序1 升级版）

在 `existing.decisions` 之外，建议为每栋补充（写进 `label` 或扩展字段，XLSX 现状台账同步）：

- 权属（国有/集体/私有/多产权）、建成年代、结构（注记自动读）、层数（注记自动读）
- 风貌评级：**保护 / 保留 / 改善（改造） / 整治 / 拆除**（常见五级，按地方导则命名）
- 质量评级（A/B/C/D 或 好/一般/差/危房）；是否违建；是否历史建筑/传统风貌建筑/不可移动文物
- 现状用途与人口/户数（涉及安置时）

出图：`ledger` 按处理方式着色即"留改拆图"；需要风貌五级时扩展 `ACT_COL`。

## 3. 留改拆政策口径（引擎自动算，务必以最新政策和地方细则复核）

实际项目应先检索现行国家文件和地方实施细则，记录适用范围、例外、时间与来源，再填写项目控制条件。不要把历史案例或脚本输出中的参考阈值作为当前项目的合规结论。

`M.renewal_stats()` / XLSX「留改拆统计」计算拆除建面占比、新建建面与拆除建面的比值。台账、统计范围和分母须先核对；安置、保护及公共服务等条件另行核实。

## 4. 控规与"六线"

| 线 | 含义 | 做法 |
|---|---|---|
| 道路红线 | 城市道路用地边界 | 建筑退让（多为 3–10m，按控规/技术规定） |
| 蓝线 | 河湖水域保护 | 同 `water.setback` 做法 |
| 绿线 | 绿地边界 | 不可占 |
| **紫线** | 历史文化街区/历史建筑保护范围 | 核心保护范围内严格控制；在 `existing.decisions` 标"保护"，校核禁止新建落入 |
| 黄线 | 基础设施用地 | 避让 |
| 黑线 | 高压走廊 | 按电压等级退让 |

实现：各线作为 `lines` 或额外 polygon 源导入；退让用 `buffer(d)`，在 `check` 前加一段自定义校核（新建体块 ∩ 退让区 > 0 报警）。建议下个城市更新项目把"六线校核"固化进 `SiteModel.check`。

## 5. 城市更新的设计判断（首版要点，待项目校准后扩展为独立 doctrine）

- **肌理优先于单体**：保留街巷格局、尺度与界面（贴线率）；新建体量嵌入而非替换。
- **微更新**：小规模、渐进式、织补式；公共空间与公共服务设施优先（口袋公园、社区服务、停车）。
- **活化利用**：保留建筑植入新业态，结合原有结构、风貌和使用条件提出适配方案。
- **可逆与分期**：改造手法尽量可逆；分期边界落在产权/地块边界上。
- **日照**：住宅日照（如大寒日有效日照时数）必须用专业日照软件校核；本引擎导出 DXF 供其使用，**不自行判定日照合规**。

# 06 · 踩坑清单（通用排查参考）

格式：**症状 → 原因 → 解法（引擎已内置处写 ✔）**

## 坐标与数据

1. **建筑落位总是漂** → 在 PDF/截图上目测 → 读 DXF 真实坐标 ✔
2. **两份测绘叠不上** → 中央子午线不同（117 vs 118.5）→ pyproj 投影变换，不靠"对齐地物"估 ✔
3. **变换后偏几十公里** → 自动解析把相邻注记"1985"的"19"读成 117°19′ → 逐条注记解析 + 同名地物校验 ✔
4. **FAR 口径说不清** → 拿地类图斑当红线；另有宗地层口径不同 → 工序0 确认法定净用地（规划条件/宗地图）
5. **现状建筑漏了好几栋** → JMD 一部分是零散 LINE → polygonize + 去重 ✔
6. **建筑全泡进溪里** → 两岸连成多边形时东岸被反向，自缠绕 → `channel_from_banks` 两种接法取合法且面积小者✔；`check` 报"压水体"✔
7. **"红线内基本平地"判断错** → 没做剖面；实际为谷地与陡坡混合 → 第一天出坡度+剖面 ✔
8. **/tmp 被清空，脚本和几何全丢** → 工作文件放临时目录 → 模型+脚本存项目 `规划图源文件/`

## 落位与设计

9. **手猜坐标反复漂（入口院落、餐厅、桥）** → 自由落位靠猜 → 拖拽板让人拖准导 JSON ✔
10. **被拆的楼又画回来了** → 拆除重建单元图省事用了原 JMD 轮廓 → 只用设计 footprint；`check` 报错 ✔
11. **桥画成小方块/角度不对/没跨满** → 猜位置 → 拖拽板定位 + 沿桥轴实测跨度 + 经项目确认的两端搭岸长度 ✔
12. **步行线穿过别墅私家院落** → 没区分私密界面 → 步行走建筑背面、从空档接桥
13. **新增体量遮挡了保留建筑的视线** → 只看平面不看台地视线 → 剖面+甲方确认，减为一簇并移位
14. **餐饮建筑侵入退让带，人工检查漏判** → 靠眼睛查退让 → `check` 机器校核门 ✔

## 数字与口径

15. **商业建筑面积算错** → 假设"最大那栋是 2 层"，实为 4 号楼 → 层数读注记（砖2）或绑定甲方编号 ✔
16. **分区图则手写了过时面积** → 手填 → 本区指标自动求和 ✔
17. **图、表、说明书数字不一致** → 改了一处没改全 → 一份模型出全部 + `stale` 扫旧数 ✔
18. **客房均建面两个值** → 表格公式只算"有客房数的行" → 统一为"客房业态建面÷客房数" ✔
19. **密度口径不一致** → 未落位预留计不计基底 → 面板分别写已落位与含预留值，两个口径都算 ✔

## 出图

# 08 · 底图冻结、生成比对与导出回读

适用：已有准确底图，需要在其上增加设计，且既有轮廓、柱网、控制边界或指定建筑必须保持。版本：geometry-guard/1（2026-10-12）。

## 先确定校验对象

- 提示词中的“冻结”是要求；只读副本、保护范围、单位、几何比对和失败退出才构成可执行检查。
- 区分原始底图、规范化副本、设计模型、导出文件、排版图像。记录转换关系。每个坐标系保留至少3个不共线控制点及两个方向的已知长度，3D还应检查标高；控制点须覆盖场地，不集中在一角。
- 初始基准必须先核对来源、尺寸与控制点。把已变形的数据冻结，只能证明它以后没再变。先做一遍“不加设计的导入—导出”，再开始创作。
- 冻结清单写明保护哪些图层/建筑编号、哪些新增设计可变；已有授权范围内的设计不需要每次重新询问。改变底图版本、保护范围或坐标变换须有明确依据，另建基准版本并保留旧版。严禁把失败结果直接设成新基准。
- 米、毫米、英寸必须显式声明；坐标转换与非等比缩放不得靠自动对齐掩盖。原点迁移、投影转换须记录正逆变换，变换后再建立经过控制点复核的统一基准。

## 容差

命令要求显式传入 `--tolerance-mm`，内部统一为米。示例的 **1mm只是数字文件保真检查示例**，不是测量精度、施工偏差或所有项目通用标准。按原图精度、转换误差和设计深度确定，记录依据。

不可为了通过而放大阈值。原技能里 `<10m` 的同名地物校验仅用于发现场地坐标带的粗大错误，**不适用于建筑、室内、柱网或导出尺寸验收**。距离、形状、拓扑、数量都要检查；总面积相同不能证明没变形。

## A. 使用现有SiteModel引擎

先核实源DXF为米制。`$INSUNITS=0` 时，只有通过已知尺寸确认后，才能在 `sources.<名称>.units` 写 `"m"`。真正的毫米文件须转换几何坐标后核验，不能只改单位标签。本引擎不会自动把源毫米坐标变成米。

```bash
# 先做一次；以下编号是示例，换成项目实际需要冻结的建筑。
python scripts/site_cli.py freeze 项目/规划图源文件/site_model.json \
  -d 项目/规划图源文件/冻结基准/v1 \
  --protect-buildings E01,B02 --tolerance-mm 1

python scripts/site_cli.py guard 项目/规划图源文件/site_model.json \
  --report 项目/规划图源文件/生成前校验.json

python scripts/site_cli.py plan 项目/规划图源文件/site_model.json -o 项目/总平面.png
python scripts/site_cli.py export 项目/规划图源文件/site_model.json --dxf 项目/方案.dxf
```

`--protect-buildings` 指 **buildings[]中的稳定编号**，不是现状台账的临时顺序号。默认基准已包含红线、现状几何、水系、道路、等高线和高程点；指定编号用于额外冻结设计模型中的既有或已批准建筑。未指定的设计建筑可继续修改。

`freeze` 生成只读底图副本、冻结清单和修改前模型副本，并向模型写入 `geometry_guard` 引用。目录必须为新目录；源文件不会被设成只读或改变。指纹用于发现意外变化，不是防恶意篡改的安全系统。

标准入口 `base / ledger / terrain / board / plan / zones / export` 及对应Python出图函数均执行生成前后检查。没有基准、底图指纹变化、保护几何变化、单位或坐标配置变化时停止；历史模型不会自动获得“已冻结”状态。`summary / decode` 可继续用于只读诊断。

生成前核对模型文件与内存数据；生成后再次核对源文件、模型及全部已生成设计几何。先写临时成果，通过后再发布，并生成 `成果名.geometry-check.json`。失败不会替换已有成果。批量分区逐文件执行，不能把已完成部分声称为整批完成。

冻结建筑在拖拽板中显示为固定参照，不加入可编辑清单。`apply` 拒绝冻结编号、重复编号和把现状多边形覆盖成矩形；合法设计回写不再额外舍入到厘米。网页拖拽本身仍是概念落位精度，不用于修改冻结底图。

### DXF导出额外检查

1. 写明米制 `$INSUNITS=6`，为红线、建筑、现状及桥轮廓写稳定编号。
2. 直接从模型生成边界基准，与待导出几何逐编号比较，包括孔洞/内环。
3. 写临时DXF，重新打开并审计；发现读取错误或需要自动修复时停止。
4. 对全部输出几何的图层、数量、坐标、标高、闭合状态、弧段参数等再次比较，并检查核心轮廓编号。
5. 通过后才发布DXF及带输出文件指纹的校验报告。

裁切后的道路、等高线等以导出前的裁切几何作回读基准；原底图副本单独保存。校验报告只认证所列范围，不代表消防、结构、规范合规或所有原CAD实体均已交付。

## B. 独立DXF或自定义商业项目脚本

不符合SiteModel标准结构的项目，**不强行迁移模型**。使用独立命令冻结指定图层；自定义生成脚本也要接入同样的源文件指纹、生成前后快照及回读比对。不能因读过此文档就声称脚本已经接入。

```bash
# 在规范化副本上选明确的受保护图层；新增方案放其他图层。
python scripts/site_cli.py freeze-dxf 已核验底图.dxf \
  -o 冻结基准/底图_v1.json --units mm \
  --layer 墙体 --layer 柱网 --tolerance-mm 1

# 生成后、SU导回DXF后或交付前重新读取实际文件。
python scripts/site_cli.py verify-dxf 冻结基准/底图_v1.json 生成结果.dxf \
  --report 几何回读校验.json
```

同目录保存 `底图_v1.source.dxf` 只读副本。支持单位 m/mm/cm/in/ft；候选文件须保持基准单位声明。实体handle重新编号允许；原图层改名、顶点顺序改变、重新分段、合并实体或类型转换可能触发保守失败，需核对转换对应关系，不能直接覆盖基准。

目前覆盖：模型空间LINE、POINT、LWPOLYLINE、2D/3D POLYLINE、CIRCLE、ARC、ELLIPSE；INSERT/MINSERT在内存递归展开并应用变换，层0继承块参照图层。选择块所在图层时包含其子实体。曲线参数、线宽、标高和闭合状态进入比较。块展开遗漏、外部参照未解析、SPLINE/HATCH/网格/实体厚度等未覆盖情况停止，禁止静默省略。TEXT/MTEXT/DIMENSION/ATTRIB/ATTDEF仅统计排除，不对文字、标注关联或排版正确性作认证。

**独立DXF检查器的读取范围，比旧SiteModel规划读取器更广。** SiteModel原有读取器不能完整保留源层中的块、弧段等；冻结时会拒绝这些情况，要求先提供展开/转换且经叠合核验的副本。不可拿“独立检查器支持块”推导“规划读取器已支持完整块建模”。

命令失败返回非零退出码；`verify-dxf --report` 保存未通过原因。未知错误或无法读取同样不能当作通过。

## SU、效果图和排版图的边界

- 原生SKP/DWG没有在本脚本中直接解析。SU里的“锁定群组”不等于跨格式保真。应保留原始模型，按已知尺寸检查导入单位、组件缩放和坐标；以标准视图/平行投影导出2D平面，再回读DXF验证。在原生SU中补核3D构件、标高与组件变换。
- 从SU转为DXF会丢失部分原生信息；DXF通过仅代表指定图层与所支持实体通过，不代表整个SKP模型已完整认证。
- AI重绘、图生图、MJ效果图只作概念表达，不作尺寸依据。需要准确空间关系时先从真实模型渲染，再在限定范围内调整材质/氛围，并复核结构轮廓。
- PNG/PDF/HTML的几何尺寸还可能受相机透视、横纵拉伸和版式影响。这里的生成检查证明输入模型未变，不认证最终像素。平面应使用正投影和等比例坐标轴，保持原始宽高比，导出后做轮廓叠合与比例尺复核。

## 失败处理与回归

记录失败环节、图层/编号、差异和容差。按“原始文件→读取模型→生成模型→导出文件→排版”的顺序定位第一次出现偏差的环节。纠正该环节后重跑；不自动平移配准、缩放、简化、修复拓扑或重建基准来让测试变绿。

```bash
python -m unittest discover -s scripts/tests -v
```

测试只用合成几何，覆盖空白导出回读、同面积变形、位置/标高/单位变化、嵌套块变换、弧段、重复/缺失实体、源文件变动、冻结对象回写、生成途中变形和失败保留旧成果。
